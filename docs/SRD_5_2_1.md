# Fifth Edition SRD 5.2.1 integration

The engine remains generic by default. `dnd_rpg_engine.rulesets.srd_5_2_1` is an opt-in rules/content integration backed by Wizards' current System Reference Document release page.

## Source policy

- Source release: **SRD v5.2.1**.
- Rules generation: **5.5e**.
- Reuse license: **CC BY 4.0**.
- Human-readable source of truth: the official SRD release page and official SRD 5.2.1 PDF.
- The D&D Beyond Basic Rules are intentionally excluded as an import source because Wizards' Creator FAQ distinguishes them from the Creative-Commons SRD.
- Long-form SRD prose is not copied into the runtime pack. The engine stores mechanical values, identifiers, provenance, and compact structured traits.

See `NOTICE-SRD-5.2.md` for attribution.

## What the runtime integration adds

The initial source-backed rules layer implements or catalogs:

- six-ability modifiers;
- the 18-skill mapping;
- level/CR proficiency progression;
- spell save and spell attack formulas;
- base armor-class behavior and configurable armor components;
- advantage/disadvantage-aware attack resolution;
- damage resistance, immunity, and vulnerability hooks;
- temporary hit points that do not stack;
- zero-hit-point handling and death-saving-throw state for player characters;
- the core SRD conditions as structured effects;
- the 12 SRD classes with hit dice, primary abilities, save proficiencies, and spellcasting abilities;
- the nine SRD species as compact trait catalogs;
- the four SRD backgrounds;
- SRD feat identifiers/categories exposed by the foundation catalog;
- six-second round timing.

The pack is deliberately mechanics-first. It does not embed hundreds of pages of descriptive rules text, setting lore, artwork, or content that appears only outside the SRD.

## Turn-based and live timing

SRD combat describes rounds and turns, with a round representing about six seconds in the game world. The bundled ruleset therefore sets `round_seconds = 6.0`.

For strict `turn_based`, the engine follows the normal readiness barrier and waits for the human actor. For `timed_turn_based`, `real_time`, `real_time_with_pause`, and `hybrid`, the engine maps readiness back onto the same six-second simulation scale. This live-mode scheduling behavior is an engine adaptation; it is not presented as an additional rule from the SRD.

## Fetching the official source

The CLI can cache the exact official SRD 5.2.1 PDF locally without blocking the async event loop:

```bash
rpg-engine fetch-srd --output .cache/srd/SRD_CC_v5.2.1.pdf
```

The fetcher:

- requires HTTPS;
- allows only the official D&D Beyond hosts configured in the source metadata;
- rejects Basic-Rules-style source paths;
- points at the English SRD v5.2.1 download linked from the official SRD release page;
- verifies that the response is a PDF;
- applies a bounded download size;
- writes the file from a worker thread rather than blocking the event loop.

Fetched PDFs are source/reference material and are ignored by Git by default.

## Loading the ruleset

```python
from dnd_rpg_engine.core.engine import GameEngine
from dnd_rpg_engine.creator.loader import install_content_pack
from dnd_rpg_engine.rulesets.srd_5_2_1 import SRD_5_2_1_RULESET, build_srd_5_2_1_pack

engine = await GameEngine.create("5E-compatible campaign")
install_content_pack(engine, build_srd_5_2_1_pack())
engine.activate_rules(SRD_5_2_1_RULESET)
```

The generic engine and the SRD integration stay separate, so another ruleset can replace this pack without changing renderers, multiplayer, persistence, or the timeline scheduler.
