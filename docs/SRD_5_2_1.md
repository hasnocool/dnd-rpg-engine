# Fifth Edition SRD 5.2.1 integration

The engine remains generic by default. `dnd_rpg_engine.rulesets.srd_5_2_1` is an opt-in rules/content integration backed by the Creative-Commons System Reference Document 5.2.1.

## Source policy

- Source release: **SRD v5.2.1**.
- Rules generation: **5.5e**.
- Reuse license: **CC BY 4.0**.
- Human-readable source of truth: the official SRD release and PDF.
- D&D Beyond Basic Rules are intentionally excluded as an import source.
- Long-form SRD prose is not copied into the runtime pack or compiled catalog.
- The catalog stores structured mechanics, identifiers, source pages, hashes, and provenance.

See `NOTICE-SRD-5.2.md` for attribution.

## Runtime rules foundation

The source-backed rules layer includes:

- six-ability modifiers and the 18-skill mapping;
- level/CR proficiency progression;
- skill proficiency and expertise;
- spell save and spell attack formulas;
- configurable armor-class behavior;
- advantage/disadvantage-aware attack resolution;
- damage resistance, immunity, and vulnerability hooks;
- temporary hit points;
- player zero-hit-point and death-saving-throw state;
- core SRD conditions as structured effects;
- 12 class foundations;
- nine species and four backgrounds;
- SRD feat identifiers/categories;
- six-second round timing.

## Offline compiled catalog

Version 1.2 adds a compile-once data path so a running campaign does not need to consult the PDF.

```text
Official SRD PDF
      |
      v
SRD compiler
      |
      +-- spells
      +-- class features / 1-20 progressions
      +-- subclasses
      +-- feats
      +-- non-weapon magic-item metadata
      +-- monster stat data (without action/gear prose)
      +-- travel / environment rules
      +-- encounter XP budgets
      |
      v
SQLite catalog
      |
      +-- CLI search
      +-- REST search
      +-- spell runtime adapter
      +-- monster entity adapter
      +-- encounter builder
```

The compiler deliberately does not retain descriptive paragraphs. Each parsed record receives a source page and a SHA-256 mechanics/stat-block hash so the generated data can be audited back to the official source without copying the source prose into every campaign save.

### Install the compiler dependency

```bash
pip install -e '.[srd]'
```

`pypdf` is optional so deployments that use a previously compiled catalog do not need a PDF parser installed.

### Fetch and compile

```bash
rpg-engine fetch-srd --output .cache/srd/SRD_CC_v5.2.1.pdf
rpg-engine compile-srd \
  --pdf .cache/srd/SRD_CC_v5.2.1.pdf \
  --output .cache/srd/srd_5_2_1.sqlite3
```

The fetcher is asynchronous, restricted to the configured official HTTPS source hosts, verifies that the response is a PDF, and applies a bounded download size. The compiler validates the document identity before writing the catalog.

### Inspect or query the catalog

```bash
rpg-engine srd-catalog-info --catalog .cache/srd/srd_5_2_1.sqlite3
rpg-engine srd-search spells "light" --catalog .cache/srd/srd_5_2_1.sqlite3
rpg-engine srd-search monsters "dragon" --catalog .cache/srd/srd_5_2_1.sqlite3
rpg-engine srd-encounter-budget "3,3,3,3" --difficulty moderate
```

A server can expose the same read-only catalog:

```bash
rpg-engine serve --srd-catalog .cache/srd/srd_5_2_1.sqlite3
```

Read-only routes:

- `GET /api/v1/srd/catalog`
- `GET /api/v1/srd/catalog/{section}?q=...`
- `GET /api/v1/srd/encounter-budget?levels=3,3,3,3&difficulty=moderate`

## Catalog coverage

### Spells

The compiler scans the complete spell-description section and normalizes spell identity, level, school, class list, casting time, range, components, duration, Concentration/Ritual flags, saving-throw ability, spell-attack type, compact damage/healing formulas, condition tags, and area-shape tags.

Simple spells can be registered into the engine's existing `SpellRegistry`. More complex spells remain fully queryable as structured catalog records rather than being reduced inaccurately to a single damage/healing effect.

### Classes and subclasses

All 12 SRD classes receive 1-20 progression rows with proficiency bonus, discovered feature IDs, subclass feature IDs, and spell-slot progression where applicable. The SRD subclass for each class is represented as a separate record and linked to its parsed feature headings.

### Feats

The compact feat catalog is available in the compiled database with category, repeatability, and source provenance.

### Magic items

The catalog stores non-weapon magic-item identity/category, rarity, Attunement flag, charge count where mechanically obvious, compact tags, source page, and mechanics hash. Long item descriptions are not copied.

### Monsters

The compiler scans SRD stat blocks and stores non-action stat data: size/type/alignment, AC, initiative, HP/formula, speed, six abilities, saves, CR/XP, defenses, senses, languages, and skills. It intentionally stops at the stat/CR boundary and does not persist action or gear prose.

`SRDRuntimeCatalog.monster_entity()` can turn one of these records into a normal engine `Entity`, so encounter generation, persistence, AI scheduling, 2D/3D adapters, and multiplayer can use the same authoritative entity model.

### Travel and environment

The compiled catalog includes travel paces, terrain pace/DC tables, extended-travel checks, special movement conversion, and structured environmental rules such as deep/frigid water, temperature extremes, heavy precipitation, high altitude, slippery ice, and strong wind.

### Encounters

The SRD per-character low/moderate/high XP budgets for levels 1-20 and CR-to-XP values are built into the catalog/toolbox. `encounter_budget()` supports mixed-level parties, while `build_encounter_candidate()` deterministically selects catalog opponents without exceeding the selected XP budget.

## Deliberate exclusions

This build does not compile weapon-specific equipment/mastery records, monster action/gear prose, detailed hazardous-substance content, or long-form descriptive SRD text. The generic engine interfaces remain capable of receiving separately provided, appropriately licensed game content without coupling those sections to the core simulation.

## Turn-based and live timing

SRD combat uses rounds of about six seconds. The bundled ruleset therefore sets `round_seconds = 6.0`.

For strict `turn_based`, the engine waits at a human decision barrier. For `timed_turn_based`, `real_time`, `real_time_with_pause`, and `hybrid`, readiness maps onto the same six-second simulation scale. This timing policy is an engine adaptation rather than additional SRD rules text.

## Loading the ruleset and runtime catalog

```python
from dnd_rpg_engine.core.engine import GameEngine
from dnd_rpg_engine.creator.loader import install_content_pack
from dnd_rpg_engine.rulesets.srd_5_2_1 import (
    SRD_5_2_1_RULESET,
    SRDRuntimeCatalog,
    build_srd_5_2_1_pack,
)

engine = await GameEngine.create("5E-compatible campaign")
install_content_pack(engine, build_srd_5_2_1_pack())
engine.activate_rules(SRD_5_2_1_RULESET)

catalog = SRDRuntimeCatalog(".cache/srd/srd_5_2_1.sqlite3")
await catalog.initialize()
await catalog.install_simple_spells(engine)
```

The generic engine and SRD integration stay separate: another ruleset can replace this layer without changing renderers, multiplayer, persistence, or the timeline scheduler.
